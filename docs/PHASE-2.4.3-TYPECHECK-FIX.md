# Phase 2.4.3 — Typecheck Fix

## Problem

The project used TypeScript 7.0.2 with Next.js 16.3.6. Next.js 16.3.6's TypeScript integration still expects the JavaScript compiler API for its normal build-time integration, while TypeScript 7 uses the native compiler package layout. This can leave generated `.next/dev/types/routes.d.ts` diagnostics in `tsc --noEmit` and can also make `next build` type detection unreliable.

## Fix

Phase 2.4.3 pins TypeScript to `6.0.3`, which retains the compiler API expected by Next.js 16.3.6.

The web workspace typecheck command is now:

```text
next typegen && tsc --noEmit
```

`next typegen` is the supported Next.js command for generating route/page/layout/handler types before an external TypeScript check.

`next-env.d.ts` is generated by Next.js and is now ignored by Git instead of being committed.

## Upgrade steps

After replacing the project files:

```powershell
Remove-Item -Recurse -Force .next -ErrorAction SilentlyContinue
Remove-Item -Force apps\web\next-env.d.ts -ErrorAction SilentlyContinue
npm ci
npm run build:research-index
npm run validate:data
npm run typecheck
npm run build
```

If the old `next-env.d.ts` is already tracked in Git, remove it from the index once:

```powershell
git rm --cached apps/web/next-env.d.ts
```

Do not disable TypeScript checking and do not use `typescript.ignoreBuildErrors` as a workaround.
